# Роли и история действий

| Действие | Оператор воды | Администратор ТСН | Технический администратор |
|---|---|---|---|
| Просмотр реестра, счётчиков, групп и истории | Да | Да | Да |
| Новые показания и кубы от старшего | Да | Да | Да |
| Исправление сохранённых данных с причиной | Нет | Да | Да |
| Создание карточек, групп и счётчиков | Нет | Да | Да |
| Выгрузка карточек и показаний в CSV | Нет | Да, с журналированием | Да, с журналированием |
| Общий журнал действий | Нет | Только чтение | Только чтение |
| Пользователи, группы и назначение прав | Нет | Нет | Да |
| Удаление записей/журнала через админку | Нет | Нет | Нет |
| Возврат старой версии через POST истории | Нет | Нет | Нет |

Технический администратор — существующий superuser. Для ежедневной работы используйте личные учётные записи с одной группой. Группы дают права на весь разрешённый раздел, не на отдельные участки. Индивидуальные дополнительные права и членство в нескольких группах складываются; штатным сотрудникам их не назначайте.

## Создание сотрудника

Технический администратор открывает «Пользователи» → «Добавить». Создаёт уникальный личный логин и пароль, затем заполняет имя/фамилию, включает «Активный» и «Статус персонала», назначает ровно одну группу: «Оператор воды» или «Администратор ТСН». Поле «Статус суперпользователя» выключено, индивидуальные права пусты. Общие аккаунты не использовать. Логин после создания в интерфейсе неизменяем. Для отзыва доступа выключить «Активный»; существующая сессия перестаёт давать доступ на следующем запросе. Смена пароля также отзывает старые сессии.

## Кто что внёс

В каждой карточке видны автор/время создания и последнего изменения; в списках — последнее изменение. Кнопка «История» показывает версии, автора, дату, причину и различия полей. Старые записи без автора честно помечены «Автор не указан», приписывать их текущему администратору нельзя.

В «Записи журнала» доступны поиск и фильтры по сотруднику, типу объекта, действию и дате. Записываются создание/изменение через админку и экспорт CSV (автор, время, количество записей). Причина исправления присутствует и в истории объекта, и в общем журнале. Стандартный журнал Django также фиксирует админские изменения пользователей/групп.

Журнал описывает действия через админку, не посещения страниц, не доставку скачанного файла и не прямой SQL. История моделей сохраняется при save(); скрипты обязаны указывать _history_user и _change_reason. Общий журнал не защищён от владельца PostgreSQL. Будущий импорт обязан иметь отдельный идентификатор операции и автора. Второй фактор обязателен для всех сотрудников.

## Рабочее место оператора воды

В списке показаний кнопка «Рабочее место оператора» открывает пакетный ввод за выбранную дату. Доступны поиск и фильтры по узлу, группе, назначению и состоянию. Видны предыдущее и следующее показания, количество внесённых и пропущенных строк. Пустые строки игнорируются. При ошибке хотя бы в одной заполненной строке пакет не сохраняется; исправные строки нужно отправить повторно после устранения ошибки.

Каждое сохранённое показание получает автора, время и отдельную запись общего журнала. Оператор может добавлять новые показания, но не исправлять сохранённые и не выгружать данные. Администратор может исправлять с обязательной причиной и выгружать показания без контактных данных в CSV.

## Установка и проверка

После migrate выполнить setup_roles. Команда повторяемая: синхронизирует только две штатные группы, не меняет аккаунты и членство. Новые версии приложения и прав проверять до production. ops/deploy-roles.sh создаёт локальный дамп, проверяет исходный коммит, применяет изменения и проверяет HTTP. При ошибке после начала переключения автоматически возвращает прежний код; добавленная метаинформация прав остаётся совместимой. Успешная установка не назначает роли существующим пользователям автоматически.

Проверки: ввод оператором; запрет исправления, экспорта и повышения прав; исправление администратором с автором/причиной; чтение истории; блокировка POST к историческим версиям, включая superuser; запрет редактирования/удаления журнала; аудит экспорта; отзыв доступа; повторная синхронизация групп. Плюс прежние проверки моделей, CSRF, перебора пароля и конкурентной версии записи.
