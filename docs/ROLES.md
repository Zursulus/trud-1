# Роли и история действий

| Действие | Оператор воды | Администратор ТСН | Закрытый реестр членов ТСН | Технический администратор |
|---|---|---|---|---|
| Просмотр рабочих лицевых счетов, счётчиков и групп | Да | Да | Только контекст участков/счетов | Да |
| Новые показания и кубы от старшего | Да | Да | Нет | Да |
| Исправление рабочих данных с причиной | Нет | Да | Нет | Да |
| Начисления, оплаты и документы кабинета | Нет | Да | Нет | Да |
| Просмотр ФИО/контактов Person и прав на участок | Нет | Нет | Да | Да |
| Связь № пользователя ↔ Person | Нет | Нет | Да | Да |
| Просмотр строк импорта с ФИО/телефоном/email | Нет | Нет | Да | Да |
| Выгрузка рабочих карточек в CSV | Нет | Да, без ПД и с журналированием | Нет | Да, без ПД и с журналированием |
| Общий журнал действий | Нет | Только чтение | Нет | Только чтение |
| Пользователи, группы и назначение прав | Нет | Нет | Нет | Да |
| Удаление записей/журнала через админку | Нет | Нет | Нет | Нет |
| Возврат старой версии через POST истории | Нет | Нет | Нет | Нет |

Технический администратор — существующий superuser. Оператор воды и Администратор ТСН — функциональные роли для ежедневной работы. Группа «Закрытый реестр членов ТСН» является специальным доступом к персональным данным: её назначают только конкретным уполномоченным сотрудникам, которым действительно нужно устанавливать связь `№ пользователя ↔ человек` и работать с Person/PlotRelation/PII-строками импорта. Она не даёт права менять воду, финансы или рабочие данные.

Если один сотрудник одновременно выполняет обычную административную работу и уполномочен вести закрытый реестр, ему допустимо назначить две группы: «Администратор ТСН» + «Закрытый реестр членов ТСН». Это осознанное исключение из правила «одна функциональная группа»: доступ к ПД должен быть отдельным и легко отзываться независимо от остальных полномочий. Индивидуальные права по-прежнему не назначать без отдельной причины.

## Создание сотрудника

Технический администратор открывает «Пользователи» → «Добавить». Создаёт уникальный личный логин и пароль, затем заполняет имя/фамилию, включает «Активный» и «Статус персонала». Для обычной работы назначает ровно одну функциональную группу: «Оператор воды», «Контролёр воды» или «Администратор ТСН». Группу «Закрытый реестр членов ТСН» добавляет только при подтверждённой необходимости доступа к персональным данным. Поле «Статус суперпользователя» выключено, индивидуальные права пусты. Общие аккаунты не использовать. Логин после создания в интерфейсе неизменяем. Для отзыва доступа выключить «Активный» либо снять только группу закрытого реестра, если нужно оставить рабочие полномочия. Смена пароля также отзывает старые сессии.

## Закрытый реестр членов ТСН

Рабочая база идентифицирует жителя человеческим `№ пользователя`, а не ФИО и не техническими `User.id` / `Account.id`. Однозначная связь `№ пользователя ↔ Person` хранится отдельно в `MemberRegistryEntry`. Полные ФИО/телефон/email остаются в `Person`, а основание владения/представительства — в `PlotRelation`.

Обычный Администратор ТСН не получает `view_person`, `view_plotrelation`, доступ к строкам импорта с ПД или `access_private_registry`. В обычной карточке лицевого счёта исторические `Account.contact_name` и `Account.phone` скрыты; CSV рабочих карточек их не содержит. Пользователь закрытого реестра может видеть эти legacy-поля только для сверки, но через обычную карточку они read-only: их очистка/перенос выполняется отдельной проверяемой миграцией после подтверждения соответствий.

Тестовый №333 запрещено связывать с `Person`. Синтетическая тестовая учётка не хранит first_name/last_name/email и предназначена только для проверки кабинета.

Подробнее: `docs/PRIVACY.md`.

## Кто что внёс

В каждой карточке видны автор/время создания и последнего изменения; в списках — последнее изменение. Кнопка «История» показывает версии, автора, дату, причину и различия полей. Старые записи без автора честно помечены «Автор не указан», приписывать их текущему администратору нельзя.

В «Записи журнала» доступны поиск и фильтры по сотруднику, типу объекта, действию и дате. Записываются создание/изменение через админку и экспорт CSV (автор, время, количество записей). Причина исправления присутствует и в истории объекта, и в общем журнале. Стандартный журнал Django также фиксирует админские изменения пользователей/групп.

Журнал описывает действия через админку, не посещения страниц, не доставку скачанного файла и не прямой SQL. История моделей сохраняется при save(); скрипты обязаны указывать _history_user и _change_reason. Общий журнал не защищён от владельца PostgreSQL. Будущий импорт обязан иметь отдельный идентификатор операции и автора. Второй фактор обязателен для всех сотрудников.

## Рабочее место оператора воды

В списке показаний кнопка «Рабочее место оператора» открывает пакетный ввод за выбранную дату. Доступны поиск и фильтры по узлу, группе, назначению и состоянию. Видны предыдущее и следующее показания, количество внесённых и пропущенных строк. Пустые строки игнорируются. При ошибке хотя бы в одной заполненной строке пакет не сохраняется; исправные строки нужно отправить повторно после устранения ошибки.

Каждое сохранённое показание получает автора, время и отдельную запись общего журнала. Оператор может добавлять новые показания, но не исправлять сохранённые и не выгружать данные. Администратор может исправлять с обязательной причиной и выгружать показания без контактных данных в CSV.

## Установка и проверка

После migrate выполнить `setup_roles`. Команда повторяемая: синхронизирует четыре штатные группы («Администратор ТСН», «Оператор воды», «Контролёр воды», «Закрытый реестр членов ТСН»), но не назначает и не снимает группы у пользователей автоматически. Новые версии приложения и прав проверять до production. Изменение схемы/прав ZUR-59 устанавливается отдельным guarded deploy с резервной копией, миграцией, `setup_roles` и smoke-check.

Проверки: оператор не видит ПД; обычный Администратор ТСН не видит Person/PlotRelation/PII-строки импорта и legacy-контакты Account; уполномоченный закрытого реестра видит их, но не получает финансовые/водные write-права; тестовый №333 не может быть связан с Person; CSV рабочих счетов не содержит ФИО/телефон; плюс прежние проверки ввода, истории, CSRF, перебора пароля, конкурентной версии записи и MFA.
