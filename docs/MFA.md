# Второй фактор для админки

Второй фактор (TOTP) доступен сотрудникам через приложение-аутентификатор: Aegis, Google Authenticator, Microsoft Authenticator или аналог.

## Политика

- 2FA добровольна для всех staff-учётных записей, включая технического суперпользователя: вход по личному паролю разрешён и без TOTP.
- Пароль и TOTP принадлежат конкретному пользователю; общих учётных данных не использовать.
- Браузер не запоминается как доверенный: если 2FA включена, при новом OTP-входе используется одноразовый код.

## Включение и отключение

После входа в `/admin/` в верхней панели есть ссылка **«2FA / безопасность»**.

Если 2FA выключена, там доступно **«Включить двухфакторную аутентификацию»**. В мастере нужно отсканировать QR-код и подтвердить первый шестизначный код. До успешного завершения мастера нажатие «Отмена» не включает 2FA.

Если 2FA включена, на странице безопасности доступно штатное **«Отключить двухфакторную аутентификацию»**. Отключение выполняется через `django-two-factor-auth` и требует текущей OTP-verification; прямого удаления TOTP-секрета из UserAdmin нет. После отключения staff или superuser продолжает входить в Django Admin по паролю.

После включения можно создать резервные коды. Секрет генератора и резервные коды не должны выводиться в UserAdmin, журналы, GitHub или служебные отчёты.

## Потерян телефон / скомпрометирован секрет

Сначала сотрудник подтверждает личность ответственному. Технический администратор с доступом к серверу выполняет:

```bash
cd /opt/trud-1-site/backend
sudo -u trudsite /opt/trud-1-site/.venv/bin/python manage.py reset_mfa ИМЯ_ПОЛЬЗОВАТЕЛЯ --yes
```

Команда удаляет старый генератор и резервные коды и завершает активные сессии пользователя. После этого старый TOTP-секрет больше не используется. Любой staff, включая технического суперпользователя, может войти по паролю и при желании подключить новый TOTP.

## Пароли

Минимальная длина нового пароля — 6 символов. Дополнительных требований к составу нет: допускаются буквы, цифры, специальные символы и пароль только из цифр. Это правило применяется при штатной установке/смене/восстановлении пароля; существующие пароли принудительно не меняются.

## Ответственность

Технический суперпользователь выдаёт сотруднику только штатную роль. Сброс второго фактора не является сменой роли и не создаёт новый общий доступ.
