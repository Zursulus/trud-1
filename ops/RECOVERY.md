# Резервное копирование и восстановление

Ежедневная задача сохраняет PostgreSQL и закрытые документы жителей в
`/var/backups/trud-1-daily`. Каждая копия создаётся во временном каталоге,
проверяется восстановлением в отдельную временную базу и только затем становится
готовой. Незавершённая копия никогда не выдаётся за пригодную.

По умолчанию каталог и файлы доступны только root, хранятся 30 дней. Для
шифрования перед отправкой во внешнее хранилище установить `age` и добавить в
`/etc/trud-1-backup.env` одну строку:

```text
TRUD_BACKUP_AGE_RECIPIENT=age1...
```

Закрытый ключ на сервере для создания копий не требуется. Его следует хранить
отдельно от сервера. После настройки запустить ручную проверку:

```sh
systemctl start trud-1-backup.service
systemctl status trud-1-backup.service --no-pager
journalctl -u trud-1-backup.service -n 50 --no-pager
```

Проверка расписания и последней копии:

```sh
systemctl list-timers trud-1-backup.timer --no-pager
find /var/backups/trud-1-daily -mindepth 1 -maxdepth 1 -type d -printf '%f\n' | sort | tail
```

Для фактического восстановления production сначала остановить приложение и
сделать отдельную страховочную копию текущего состояния. Затем проверить
`SHA256SUMS`, расшифровать файлы при необходимости, проверить дамп через
`pg_restore --list` и восстановить его с `--clean --if-exists --exit-on-error`.
Каталог `private-data` восстанавливать как единое целое, сохраняя прежний каталог
до завершения проверки. После запуска выполнить `manage.py check`, открыть сайт,
админку и кабинет жителя. Эту операцию проводит администратор сервера: она
заменяет рабочую базу и поэтому намеренно не запускается таймером или веб-интерфейсом.
